02

Commerce CDC

Data engineering

Keeping warehouse history correct when database changes arrive late.

An incremental commerce warehouse with customer history, current orders and a paid-revenue view. It rebuilds affected entities, independently checks published rows and repairs drift from its source journal.

Engineering focus

Source-order history, zero-write replay and atomic publication. An independent Python reconstruction checks the SQL output; an explicit repair rebuilds derived tables without changing the journal.

Technology

Python · SQL window functions · SQLite · SCD Type 2

Evidence & limits

Twelve synthetic deliveries produce nine accepted changes, five history versions and one current order. Paid revenue reconciles to 15,000 AUD cents. Thirteen tests cover replay, late changes, deletes, rollback, drift repair and randomized arrival order. With 2,000 synthetic customers and 2,000 orders, one customer update writes five derived rows; a full rebuild of that state writes 12,002. These are write counts, not a throughput benchmark. This is a local sink for normalized events; no live CDC connector or production-scale benchmark is included.

04

SignalForge

ML data engineering

Training on information that was actually available at prediction time.

A predictive-maintenance data pipeline that excludes future and delayed sensor readings. One SQL feature definition produces reproducible training snapshots and a local serving snapshot, with coverage checks for missing and expired readings.

Engineering focus

Check both event time and first availability, enforce a one-hour freshness limit and measure coverage against expected machines. A rejected release preserves the last good features, cutoff and quality report.

Technology

Python · Temporal SQL · SQLite · Content hashes · Feature snapshots

Evidence & limits

At the fixture's 10:00 prediction, the pipeline selects the known 68°C reading and excludes a delayed 82°C reading and a future event. Seventeen tests cover leakage, training/serving parity, freshness, coverage thresholds, rejection and recovery. The demo blocks an incomplete three-machine release and proves the prior generation remains intact. Telemetry is synthetic; no model, hosted API or production performance is claimed.

Understanding the next day through historical energy data.
